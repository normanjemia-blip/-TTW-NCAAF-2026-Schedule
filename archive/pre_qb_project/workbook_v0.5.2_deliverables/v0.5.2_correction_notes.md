Base: **v0.5.1** (not modified — copied first, then edited). `v0.4.2` and
all earlier versions remain untouched. Phase 6 not started.
**Status: pending independent approval.**

## What was wrong

v0.5.1 introduced a documentation/implementation mismatch. Its
documentation text (`DICTIONARY!B12:B14`, `DATA QUALITY!A2`/`A11`) was
already written to call the transitional-reclassifier status
**"TRANSITION UNCERTAIN"** — but the actual formula that produces that
status (`ENGINE!AI`) and the counter that tallies it
(`DATA QUALITY!B11`) were never updated to match; both still
returned/counted the old string **"FCS/TRANSITION UNCERTAIN"**. The
workbook disagreed with its own documentation.

## What changed (exactly 5 things, nothing else)

1. **`ENGINE!AI6:AI1005`** (1000 cells): the returned string
   `"FCS/TRANSITION UNCERTAIN"` → `"TRANSITION UNCERTAIN"`. **Nothing
   else in the formula changed** — same `IF` nesting, same priority order
   (`BLOCKED` > `FCS — NO PLAY` > `PENDING LINE` > `STALE LINE` >
   `QB UNCERTAIN` > `TRANSITION UNCERTAIN` > `DATA INCOMPLETE` > `READY`),
   same trigger condition (`$AF{r}<>""`). Verified by an assert-before-
   overwrite check against every one of the 1000 rows' exact prior text
   before any edit was made (`build_v052_formulas.py`).
2. **`DATA QUALITY!B11`**: `=COUNTIF(ENGINE!$AI$6:$AI$1005,"FCS/TRANSITION UNCERTAIN")`
   → `=COUNTIF(ENGINE!$AI$6:$AI$1005,"TRANSITION UNCERTAIN")`.
3. Every other remaining reference to the old string was located and
   corrected: `CHANGELOG!C35` (v0.5.1's own change-description entry
   still said `"FCS-TRANSITION UNCERTAIN"` in its priority-order recap
   and `"FCS/TRANSITION UNCERTAIN"` in its live-calc scenario recap —
   both fixed) and the deliverables' summary/unit-test text (see below).
4. **`CHANGELOG!C37`** range typo: `"CLEAN!AC1005"` → `"CLEAN!AC6:AC1005"`,
   matching the actual 1000-row range (`AC6:AC1005`) that v0.5.1 edited.
5. Version banner and a new `CHANGELOG` entry (row 43) → v0.5.2.

## What did NOT change (verified, not assumed)

The `FCS — NO PLAY` logic, effective-game exclusions (`CLEAN!AB`/`AC`),
NDSU/Sacramento State's classification and transitional safeguards, QB
state (still 0/138 loaded), TTW-prior state (still blank/blocked), FCS
TIERS (still empty/inactive), and every value, format, schedule row, and
SETTINGS constant. The full diff vs v0.5.1 (`v0.5.2_vs_v0.5.1_full_diff.tsv`)
shows changes in exactly 4 sheets: `ENGINE` (1000 cells, `AI` only),
`DATA QUALITY` (1 cell, `B11`), `START HERE` (1 cell, banner), and
`CHANGELOG` (6 cells: the 2 corrected v0.5.1 entries + 4 cells of the new
v0.5.2 entry... precisely, `C35`+`C37` corrected plus the new row's 4
columns). The diff vs the ultimate approved base `v0.4.2` shows exactly
the same 8 sheets v0.5.1 touched, with one additional formula cell now
different (`DATA QUALITY!B11`, which v0.5.1 had left pointing at the old
string) — **4,001 formula cells total**, not a single one outside
`ENGINE!AI` and `DATA QUALITY!B11` changed further.
