## What changed, in one paragraph

FBS-vs-FCS games are now permanently excluded from every betting
calculation. They keep their schedule entry and, once played, their
final score — for reference only. `ENGINE!AI` (STATUS) reports the new,
permanent value **"FCS — NO PLAY"** for them; no market line is required,
and no spread, total, team total, edge, label, or confidence score is
ever calculated. They're excluded from missing-line counts and from the
actionable DASHBOARD ranking, and their results contribute nothing to
effective-game counts or weekly power-rating movement. North Dakota
State and Sacramento State are unaffected — both remain ordinary
FBS-reclassifying teams under the existing, untouched transitional
safeguards.

## The formula work — full trace before editing anything

Before changing a single cell, the complete existing formula chain around
FCS handling was traced end-to-end (`formula_change_design.md`) to find
the *minimal* correct change. Most of the required behavior turned out to
already cascade for free from existing guard clauses, once FCS TIERS'
rating data is simply not populated — spread/total/edges/team-totals/
labels, the DASHBOARD priority ranking, and the weekly rating-movement
pipeline all already short-circuit to blank/zero once the FCS-side rating
is blank. Only **4 formula patterns** needed an actual edit, applied
uniformly across all 1000 game rows (6:1005) — **4,000 formula cells**:

1. **`ENGINE!AI`** (STATUS) — new `"FCS — NO PLAY"` branch, ranked after
   `BLOCKED` (a genuine schedule data-integrity issue still surfaces) and
   before every line/QB/transitional check (none apply to a permanently
   non-actionable game).
2. **`ENGINE!AJ`** (Confidence) — added to the existing blank-output
   guard list, so no confidence score is ever computed for these games.
3. **`CLEAN!AB`** (eg_home) and **4. `CLEAN!AC`** (eg_away) — removed the
   old partial-credit (0.5x) branch for FCS opponents; they now
   contribute exactly 0 toward effective games, same as a bye.

Full before/after text for every pattern is in `formula_change_design.md`
and the workbook `CHANGELOG` (9 new v0.5.1 entries, one change documented
at a time, per your instruction).

**Nothing else was touched.** `CLEAN!R`/`S` (the FCS-tier lookup formulas
themselves) were deliberately left unchanged — with FCS TIERS empty they
already always resolve to blank, which is the actual mechanism that keeps
FCS opponents rating-less. This was a considered decision, not an
oversight: touching them wasn't necessary, and minimizing the diff
minimizes risk.

## Live-calc validation, not just a manual trace

The 4 changed formula patterns were extracted **byte-for-byte** from the
real `v0.5.1_working.xlsx` and evaluated with a real Excel-formula engine
(`build_unit_test.py`, `unit_test_model.xlsx`) against 5 scenarios:
FBS-v-FBS with/without a market line (→ PENDING LINE / READY, unaffected
baseline behavior), FBS-v-FCS with no line (→ **FCS — NO PLAY**, not
PENDING LINE), FBS-v-FCS that's *also* BLOCKED via a duplicate GameID
(→ **BLOCKED** correctly outranks FCS — NO PLAY), and a transitional
reclassifier game (→ **TRANSITION UNCERTAIN**, confirming that path
is untouched and distinct). **All 10 assertions passed** (5 status
values + confidence blanking + 4 effective-game values).

## FCS TIERS — retained, emptied, marked inactive

No rating data is loaded or maintained. The tab is kept (not deleted)
only because `CLEAN!R`/`S` structurally reference it; `A1`/`A2` now read
**"INACTIVE / NOT USED"** with an explanation. `DICTIONARY` and
`DATA QUALITY` text updated to match (new suppression-priority order,
a reference-only "FCS — NO PLAY" count added to `DATA QUALITY`,
explicitly labeled not a data-quality issue).

## TTW independent 2025 prior — re-investigated further, still blocked

Beyond the two paths already confirmed blocked, this pass tried the
GitHub API release-metadata endpoint, two independent GitHub-content
proxies (jsdelivr, raw.githack/statically), and Hugging Face/Kaggle
dataset search. All confirmed the same root cause: GitHub **Release**
assets live outside the git tree every content proxy mirrors, so no
proxy can route around the session's repo-scope gate — only direct
GitHub access (blocked) or a user-supplied file can reach it. No
unverified third-party mirror was substituted. Full detail and the
retrieval procedure: `ttw_prior_recheck_v051.md`.

## QB research — continued, with a more precise diagnosis

Went beyond re-testing ESPN's empty depth-chart API: genuine web research
across reputable outlets identified a handful of programs with a
low-ambiguity reported 2026 starter (returning multi-year starters,
no reported competition) — listed for reference in `qb_research_v051.md`,
**not loaded**. The reason: even a well-confirmed starter name satisfies
only 1 of the 6 required fields. There is no approved, verified source or
methodology anywhere in this project for the numeric baseline/adjustment-
value fields — a deeper gap than API availability, and (learning from
this session's FCS-rating episode, where a self-built methodology was
constructed without asking first and was then removed) **not something
filled in unilaterally this time**. QB VALUES remains 0/138 loaded,
unchanged.
